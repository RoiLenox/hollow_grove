# Being Object Root Ontology V1

This document records the locked Hollow Grove Being/Object root ontology as enforced code.

It extends the existing semantic foundation, Point/Point² progression, Rule-of-Twelve geometry, and Proxy/Moxy/Foxy manager language. It does not replace the frozen Version 1.1 execution path.

The embodied Flow / Glow gesture grammar layered over this ontology now lives in:

- `CURRENT_GRIP_INHERITANCE_V1.md`

## Root Doctrine

- `Being = living practiced Hueman identity and embodiment`
- `Object = external addressable thing or construct`
- `Skill = practiced relation between Being and Object`
- `Move = active Form- or Frame-specific expression of that Skill on that Object`
- `Hollowing = refinement within Being or Object`
- `Synthesis = transfer or crossing of qualities between Being and Object`

Canonical relation:

- `Being acts.`
- `Object receives or participates.`
- `Skill relates them.`
- `Move expresses the relation.`
- `Hollowing perfects a side.`
- `Synthesis crosses the boundary.`

## Being

Being remains the persistent Hueman-derived practiced self.

Runtime meaning includes:

- `persistent Hueman identity`
- `current form`
- `paired aura lineage context where representable`
- `Flow learnset`
- `Glow learnset`
- `CurrentPrism`
- `stable point level`
- `embodiment`
- `natural inheritance`

Being state is projected from the existing Point and FrameState surfaces. It does not replace progression truth already stored elsewhere.

## Object

Object remains its own side.

Canonical Object support includes:

- `identity`
- `kind`
- `material`
- `condition`
- `functions`
- `connections`
- `modification history`
- `synthesis history`

Object is not restricted to a small item. It may be:

- `mechanism`
- `terrain`
- `structure`
- `system`
- `material construct`

## Skill

Skill is not a free-floating stat.

A Skill records practiced relation between:

- `one Being`
- `one Object family`
- `repeated meaningful use`
- `Current investment`
- `Aura investment`
- `pressure exposure`
- `context familiarity`

Canonical witness in code:

- `Grip`
- `Repair`
- `Brace`
- `Guard`
- `Climb`

## Move

Move is a resolved expression, not the root Skill itself.

Canonical grammar:

- `Being + Skill + Object + Addressing Mode + Aim -> candidate Move`

Then:

- `candidate Move -> Recipe -> V2 Evaluate / Choose -> V1.1 Execute`

Canonical witness fixtures:

- `Gremlin + Grip + Mechanical Latch + Proxy -> TinkerGrip`
- `Troglodyte + Grip + Fractured Cliff + Proxy -> World Grip`
- `Gremlin + Repair + Door Mechanism + Moxy -> System Repair`
- `Gremlin + Repair + Damaged Mechanism + Foxy -> Return Repair`

Runtime lock:

## Hollowing and Synthesis

Hollowing stays on one side:

- `Hollow Being`
- `Hollow Object`

Hollowing must declare its target side explicitly.

Synthesis is the crossing capability:

- `Object trait -> Being`
- `Being trait -> Object`

Synthesis remains bound to the existing Recipe legality boundary. It does not bypass V2 evaluation or frozen V1.1 execution.

Canonical synthesis witness:

- `Gremlin + Stone Architecture + Brace / Guard / Climb`
- cross-boundary trait transfer is representable
- recipe boundary remains explicit

## Proxy Moxy Foxy Addressing

Addressing mode is not Skill, Object, or Aim. It is how the Being addresses the Object relation.

- `Proxy = immediate/local Being-Object relation`
- `Moxy = relation through what the Object connects toward`
- `Foxy = inverse, reflected, hidden, or return relation`

Manager lock remains:

- `Proxy = PLEB = Clouseau`
- `Moxy = META = HAL`
- `Foxy = BLEP = Cleopatra`

## Boundary

The locked pipeline remains:

- `Observe -> Generate -> Evaluate -> Choose -> ChosenDecision -> Recipe -> V1.1`

The frozen V1.1 execution topology remains:

- `Point -> Triway -> Fourway -> HollowGrove -> CurrentSeam -> AuraBeam -> Point²`

Being/Object interpretation lives above V1.1. It does not introduce new kernel landing states.
