## Fixed geometry

The constitutional runtime maps the existing four-variant `House` type to
fixed kernel coordinates:

```text
Stonebend       = [    0, 0, +1000]
Sandmanor       = [+1000, 0,     0]
Glaüshouse      = [    0, 0, -1000]
Flynt           = [-1000, 0,     0]
CentralJunction = [    0, 0,     0]
```

Central Junction is represented separately from `House`. It is an actual
coordinate and relation, not uncertainty, a fifth House, a moral midpoint, or
automatic synthesis.

The isolated universal kernel retains its House-neutral boundary. It owns the
bounded integer math and names the five positions by axis relation; the root
constitutional layer attaches the immutable House and Central Junction names.

## Numeric law

- Absolute axes are signed integers from `-1000` through `+1000`.
- Translation axes are signed integers from `-2000` through `+2000`.
- Canonical coordinates never use floating point.
- V1 positions require `y = 0`.
- V1 translations require `dy = 0`.
- Nonzero Y is rejected, including during deserialization.
- Values are never clamped or silently normalized.
- Movement is valid only when `source + translation = destination`.
- Distance comparison uses squared Euclidean distance without square roots.

## Relationship law

All four House distances are returned. Stable tie order is:

```text
Stonebend
Sandmanor
Glaüshouse
Flynt
```

A coordinate may therefore retain several House relationships. A nearest
House is a derived reading, never identity, ownership, containment, authority,
or exclusive classification.

Language is not stored as a closed synonym dictionary. A later interpreter may
propose nearby coordinates for contextual synonyms and distinct coordinates
for the same expression at different scales. Rust stores only witnessed,
scope-specific confirmed positions.
