## C. Exact mathematical rules

All palette hex strings are fixed 8-bit sRGB RGB values. Calculations below operate **per RGB channel**, not in CIELAB/OKLab. These are reproducible RGB arithmetic rules, **not** claims of perceptually uniform shade spacing.

1. **Three intermediate positions (3, 5, 7)** for Stonebend, Sandmanor and Glaüshouse are componentwise midpoints of positions `(2,4)`, `(4,6)`, `(6,8)` respectively. For integer channels `a,b` from 0..255, use **half-up rounding**: `mid(a,b) = (a+b+1)//2`.
2. **Flynt grayscale** at *every* position is derived from the corresponding Stonebend blue: `gray = (red + green + blue + 1)//3`, then set each channel to `gray`. This equals nearest-integer rounding of the arithmetic mean for 8-bit integer channels. Example: Gremlin `#0B1026` → Gargoyle `#161616`.
3. **Black/White mixing**, when intentionally used for visual rendering, is channelwise RGB interpolation: `black_mix(c,t) = round((1-t)*c)` and `white_mix(c,t) = round((1-t)*c + 255*t)` with `0<=t<=1`. Do **not** silently mix or recolor every region. Mixing is a renderer/asset choice and does not change source palette tokens.
4. **Previous 5-slot → new 8-slot index migration:** `1→1`, `2→2`, `3→4`, `4→6`, `5→8`. Keep backwards compatibility for existing asset references and avoid assigning old index 3 to new color level 3.
5. Protect all **22** approved v1.x colors unchanged. This revision adds **12** colors (levels 3,5,7 in each House), yielding exactly **34** values.
